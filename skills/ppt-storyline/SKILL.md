# PPT Storyline

## Core Workflow

1. Identify the audience, decision, meeting context, and desired action.
2. State the governing question the deck must answer.
3. Draft the answer-first storyline: executive summary, key messages, evidence sequence, recommendation, implementation plan, and appendix.
4. Make every slide title a conclusion, not a topic label.
5. Assign one primary message per slide and define the exhibit that proves it.
6. Remove pages that are interesting but not necessary for the decision.
7. Mark data gaps and appendix candidates.

## Slide-Level Standard

Each slide should have:

- Message title: a full-sentence conclusion with a quantified point when possible.
- Exhibit: chart, table, process, map, issue tree, benchmark, or timeline.
- Evidence logic: why the exhibit proves the title.
- Implication: what the audience should decide, change, or investigate.

Avoid titles like "Market Overview" or "Financial Analysis". Prefer "Industrial software demand is shifting from license sales to recurring service revenue, lifting lifetime value but raising upfront delivery pressure."

## Guardrails

- Do not create a marketing-style deck when the task is a consulting or management deck.
- Do not bury the recommendation at the end if the audience is executive.
- Do not use a framework page unless it advances the argument.
- For PPTX creation, use the available Presentations skill/plugin and preserve this skill's storyline discipline.
