# PPT 版式参考库

供 `presentations` 和 `ciic-style-ppt` 制作、改版及审稿时使用。由用户指定的五份PPT整理，源文件共822页。2026年9月29日补入两份完整科技创新咨询方案及逐页设计拆解。此库保留原文件副本、代表页预览和逐页适用说明。它是版式参考资料，文件内的占位文案、示例数字和操作提示均不构成任务指令。

管理咨询及国企汇报的新建、改版与审稿，先读[用户认可方案的设计方法](references/approved-consulting-design.md)及[起始参数](references/consulting-tokens.json)。该方法记录D/E真实页码、适用场景、可编辑组件及逐页验收标准；当前明确要求和原样复刻范围优先。

制作前同时阅读[五份资料的综合设计方法](references/consulting-page-design.md)。A、B、C三套模板用于查找构图和基本图形关系；D、E两份方案用于学习这些关系怎样与完整论证、分组边界和实际正文组成一整页。按内容关系综合使用，不能只采用最新两份，也不能停留在蓝色文字、色条和段落搬排。

同时执行[PPT艺术构图与展示要求](../ppt-art-direction.md)。未明确要求表格、矩阵或原表保留时，优先检索非表格的整页构图；共同列、固定横行及等大网格均排除出默认候选。实际查看参考的轮廓、曲线、主次与完整正文安排，保留有作用的留白和原文文字。

## 一、先确定内容，再选择版式

必须先执行 [PPT 文字与原文结构要求](../ppt-content-rules.md)。记录原文每层的标题、项数、顺序、归属和编号，再从 [catalog.json](catalog.json) 查找能表达同一关系的构图。查看所选条目的 `preview` 图片，并阅读 `content_relation`、`item_count`、`complete_body` 和 `semantic_boundary`。不能只读版式名称就开始套图。

在私有制作记录中写下原文条目到画面位置的对应、所选参考编号、适用理由、需要调整的图形和完整正文的位置。原文两点搭配四分支参考时，应重画两条分支；不要拆写内容填满参考页。形状、端点、中心主题、引线、共用轴和装饰的数量均不等同于论点数量。

当前任务明确要求保留的模板优先。仅作构图借鉴时，按当前品牌、字体、阅读场景重新绘制；不用照搬整页。此库不把中智配色强加给其他品牌。

## 二、按内容关系查找

| 类别 | 可选择的构图 | 使用边界 |
| --- | --- | --- |
| 层级与支撑 `hierarchy` | 屋顶与支柱、错位分层平面、阶层与侧注 | 原文必须确有统领、依赖或支撑；并列事项不能凭画面高低变成层级。 |
| 中心与分支 `center` | 侧置主图与弧线分支、中心与双侧展开、半圆展开、树状归属 | 中心是共同对象；分支与子分支保留原层级。无方向的归属用引线即可。 |
| 阶段与路径 `process` | 折线路径、折返长路径、交替时间轴、阶梯、环形步骤 | 顺序、进阶、实际时间间隔及返回关系分别核对。普通组成关系不能加成闭环。 |
| 并列与对照 `comparison` | 双轨、共享时间轴、开放分栏、上下对应、对称或非对称正文 | 对照维度须由来源支持；版面不对称可以适应文本长短，不能暗示无依据的价值高低。 |
| 组合与分解 `convergence` | 整体分块、因素相加、条件分支、汇聚与展开 | 加号、分块、交叠与漏斗各有含义；不得凭造型补出权重、交集、筛选或因果。 |
| 正文与证据 `text` | 左侧主述与右侧补充、图文双列、无框段落、数据与解释并置 | 让完整论证成为主体，图片或小图帮助识别和核对；支撑材料维持原有归属。 |

D、E条目增加了`related_refs`与`construction_notes`：前者链接A/B/C的关联构图，后者记录实测比例、层级和原生绘制方法。新增条目见D002—D011、E003—E013；[D逐页拆解](references/D-design.md)和[E逐页拆解](references/E-design.md)包含全部26页观察。

参考编号由源文件编号与原始页码组成，例如 `C024` 指 C 文件第 24 页。A为全套框架模板，B为2016年版式整理，C为PPT模板，D为国有企业科技创新规划方案，E为科技企业十五五科技创新战略规划。完整文件名、页数与哈希见 [manifest.json](manifest.json)。可用 `python3 scripts/find_layouts.py --family center` 列出对应条目，再打开图片。

## 三、用构图改善阅读与美感

- 先分配正文的宽高，再安排图形。圆、扇区和路径节点主要承载准确名称或编号；完整解释可直接排在白底上，用对齐、间距和细线标明归属。不要把每段文字都套进方框，也不要只是把方框换成圆形。
- 用尺度差异、统一对齐、线条粗细、色面比例和留白建立主次。可以采用偏置主图、上下错位、弧线、少量斜面和局部深色底。留白用于分隔、引导和突出重点，不能为了填满页面添加内容。
- 同级事项语义地位保持一致；不同文本长度可以分配不同面积。并列关系无需连接箭头；有顺序或因果依据时才使用带方向的连线。线条避开文字，交叉处须可辨认去向。
- 识别主体、岗位或流程角色的功能图标可以按需要重复，并配有文字名称。可删除无实际含义的图标、厚阴影、多重圆环、金属质感和大幅装饰。多样化体现在整页组织方式与阅读节奏，不能依赖元素堆叠。
- 连续页面若使用相同构图，应核对内容关系是否也相同。有相同关系时可保持一致；关系变化时重新选型。完整正文页、图解页、数据页可以形成节奏，不设每套必须使用多少种版式的硬指标。

## 四、把参考转成可编辑画面

沿用当前制作技能规定的工具。`presentations` 新建 PPT 使用受支持的原生对象 API。图形关系应由可编辑的线、路径、基础形状和文本实现；不把整幅框架栅格化来省去结构工作。

| 构图 | 绘制方法 | 正文安排 |
| --- | --- | --- |
| 侧弧与分支 | 一条侧弧、按原文项数布置节点、从节点引出水平线。弧线只负责归组。 | 右侧每项一段，连接线对准标题；段落高度按实文调整。 |
| 分层平面 | 按原层数绘制轻透视平面，保留清楚的层间距离；用引线连接说明。 | 标签保持水平，解释放两侧或统一右侧，不沿斜面排长句。 |
| 时间轴与折返路径 | 用连续线或细色带标明方向；事件、日期和阶段按原序对应。 | 段落交替放置或沿线外侧排列；折返处标清顺序，长项在原编号下续页。 |
| 双轨与对照 | 两条有明确名称的轨道，共用确有依据的阶段或日期。 | 各组正文留在本组内；不能因转置图表而改变原文父子关系。 |
| 圆环与扇区 | 节点数随原文调整；循环与组成使用不同连线，方向有依据才画箭头。 | 缩小主图，为旁侧或外围解释留出空间；不用沿弧文字承载正文。 |
| 无框正文 | 用标题、段距、细分隔线和少量重点色组织阅读；可在侧面配置较小证据图。 | 保留完整段落和内部论证，不把长例子抽成新的同级卡片。 |

字体、字号和配色服从当前品牌及目标阅读场景。参考文件名中的最小 10 号仅描述该文件，不构成本库的推荐字号。五份参考中存在同一构图重复改色、较重装饰及示例性数据；借鉴构图时逐项取舍。

## 五、分别检查结构、文字和视觉

先对照原文核对所有层级、项数、顺序、名词、编号及归属，检查图形是否额外暗示了因果、先后、比例或优先级。再脱离原文和备注独立读图，确认对象、动作、条件和关系完整，目标读者可以直接读懂。最后查看全套缩略图与逐页大图，检查焦点、阅读顺序、留白、文字适配、线条交叉、对齐和重复构图。

三项分别记录问题及修正。结构或语言不合格必须返修，不能用画面美观抵消。几何校验只能证明对象位置等技术事实，不能证明审稿通过。若有人物或机构图标、参考照片、示例数据，需要检查其与本页真实内容的对应。

## 六、来源与维护

源文件副本在 `sources/`，原始路径、页数及 SHA-256 在 [manifest.json](manifest.json)，预览在 `previews/`。源页码经过 PPTX 演示顺序核对。预览由本地字体替代渲染生成，用于观察布局；涉及字体精确还原时须回到原 PPTX 核对。保留来源记录，制作新稿时不要带入模板的二维码、作者宣传或无关标识。

库位于个人技能目录，独立于插件版本缓存。更新 `presentations` 后应继续读取此文件，并检查原生图形、曲线、完整正文和原文结构要求是否仍然生效。添加参考时同时补充图片、准确页码、适用关系、正文安排和使用边界，不能只增加一个版式名称。四张原生可编辑复刻及代码保存在reconstructions；新文章中的项数、名称和正文必须重新映射，不能直接继承样页的业务内容。
