# 以认可原稿校验设计迁移

用于参考稿明确、需要学习其设计能力的制作与技能验证。先实际看来源和成品，再读技术结果。颜色、字体、无溢出和可编辑性分别证明对应属性，不能据此判定设计已经达到参考的水平；图片为零、原生形状数量多也不构成审美优点。

## 先比较六项设计工作

| 比较项 | 在来源与成品中分别记录 | 需要返修的具体情形 |
| --- | --- | --- |
| 论证深度 | 页面总述、父项、专业对象、具体行动、必要条件分别在哪里 | 只保留屋顶、色条等外轮廓，原稿多层工作退成几句泛化描述；用过短虚拟内容验证复杂方案能力。 |
| 主体及比例 | 第一眼的主体、主图/解释/证据面积、对应内容负荷 | 主图被缩成角落小图，正文先占固定区域；多个不同关系被统一改成同宽同高容器。比例以当前完整内容和参考为依据，不设占用率指标。 |
| 图形功能 | 每个子图、端点、边界、方向线各承担什么含义 | 删除目标端点后让箭头指向空白；保留图形名称却取消其归组、支撑、承接或验收作用。删去某图时须记录其功能由哪里承担。 |
| 文字层次 | 结论、组名、对象名、完整正文、段内重点如何区别 | 所有内容都只有蓝标题和深灰段落两层；反复添加同样方点、色条或图标来替代分析。段内重点只强调真实动作、条件和判断。 |
| 线条与空间 | 对齐基线、连线端点、线宽、分隔与留白的具体职责 | 线条穿字、悬空或多条线职责不明；留白只是固定文本高度留下的空档。等距、开放正文和对称均可用，但要服务当前关系。 |
| 全套节奏 | 不同页的内容关系、阅读深度及适用场景 | 为统一外观而让不同关系都变成卡片；或机械轮换图形。按内容选取架构、过程、分类、对照、开放正文与证据组合。 |

虚拟验证内容须具有足够真实的专业深度，能够测试来源中多个关系如何共处；不编造真实企业事实。实际客户内容按原文取舍与结构规则执行，不能为追求密度补充内容或为了清爽删除必要解释。

| 来源 | 应保留的工作方式 | 可编辑实现及适配 |

| [E9](../previews/E009.png) | 三级转化链条、项目分类矩阵与场景验证说明在一页保持各自身份 | 以不等宽区域组合阶段牌、定性矩阵与开放正文。矩阵须有明确轴和分类依据，保留目标、行动与条件；不可退成三个同样的栏目。 |

组件提供`pageFrame`、`richText`、`continuousSlope`及基础原生绘制：页头按实际标题和总述调整；富文本保留一个段落并突出必要动作；连续斜边避免错台。它们提供语义组合的支点，不自动决定论证、图形关系或页数。

`richText`保留原生段内样式，不能保证导入渲染后的行数。实作发现，较长的同式文本run可能从新行开始；改用完整字符串加文字范围样式也会出现同一现象。遇到这种情况，按语义显式换行并预留实际高度，或用完整正文配就近强调标签；不要只按字符数认定富文本能放下，也不要因PPTX只有一个段落就忽略实际排字。

原生表格还要检查目标引擎的行高余量。声明的表框高度、实际导入显示和原生表格自动扩高估计可能不同；字号、单元格内距、行数和基线空间须共同容纳。出现`native_table_overflow`时，定位并调整行高、表格位置及下方说明，重新导入看图并运行原版检查器，不能仅凭当前预览未遮挡宣布完成。较长的全局注释宜用独立原生说明对象，避免塞入合并格后把某一数据行撑高；保留表格的真实空白与岗位映射，明确注释身份，不改检测器阈值规避问题。

## 实际比较与修订

1. 同尺度并排查看来源与新稿，记录原稿的第一焦点、内部子图、端点、分组边界和文字层次，以及新稿如何承担相同功能。
2. 用有真实复杂度的内容完成试制，先对照完整内容与语义，再观察整页主次和细节。来源中有混合字体、拥挤或转换缺陷时分别处理，不把缺陷当成标准。
3. 由未参与该页制作的人实际看图，提出具体保留及修改理由。重要设计迁移至少完成一轮依据对照意见的实质修订，记录改了哪些关系、比例、焦点或排字。
4. 修订后重新导入最终文件并渲染受影响页面及全套缩略图；再次并排核验。审阅结论陈述已解决的问题与仍有差距的地方，不使用伪装客观的美感分数，不替用户宣布认可。

技术校验记录与设计比较记录分开保存。最终交付保持原生对象及必要素材可用，不用整页截图替代用户要求的编辑能力；适合的图表、矢量和图片可以使用，是否采用由内容和任务决定。
