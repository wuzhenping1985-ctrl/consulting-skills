# 用户认可的咨询方案设计方法

供本用户管理咨询、国企汇报的页面规划、制作及审稿使用。沿用当前任务要求、[原文结构规则](../../ppt-content-rules.md)及[艺术构图规则](../../ppt-art-direction.md)。来源为D《国有企业科技创新规划方案V20260525 (1).pptx》12页、E《科技企业“十五五”科技创新战略规划-20260525.pptx》14页；页码均按PPT演示顺序。源文件和SHA-256见[manifest](../manifest.json)，逐页观察见[D](D-design.md)、[E](E-design.md)。来源中的业务内容和案例保持参考资料身份。

制作与验收还须执行[以认可原稿校验设计迁移](reference-transfer-review.md)，先对照整页信息工作、子图、端点与正文层次，再进行技术检查。样页要能测试真实咨询复杂度，不能用过短的虚拟段落证明复杂方案能力。

## 先作六项设计选择

| 选择 | 从认可材料学到的做法 | 页码依据与使用边界 |
| --- | --- | --- |
| 页面要表达什么 | 标题说清本页判断，主体用证据或关系展开；完整说明紧贴所属对象。总述已经清楚时可直接进入图解，不强加重复副标题。 | D4–D9、E4/E6/E11。新写分析页用有证据的判断标题；目录、定义及须保留的来源标题不强改为结论。 |
| 全页用什么关系 | 先画全页骨架，再安排每组内部关系；上层可以共用流程或总目标，组内仍分别采用支撑、组成、层级或阶段。 | D4四阶段各有不同子图；D5/D8架构与侧案例；E6目标、原则、任务、保障，以及任务层内1+3。普通并列事项不升级为阶梯或闭环。 |
| 文字放在哪里 | 名称进标签，完整句子留在对应组内。边界只用来表明父项、子项或案例；开放正文同样可以承载较长说明。 | D7论点与案例纵向对应；D9父项内两类子项；E11正文上下错开。图解与完整文字共同工作，不靠删除解释换空间。 |
| 各区多大 | 按关系复杂度和正文容量分配面积，主图、解释、案例可有不同宽度；同级地位不要求等面积。 | D5主图约64%页宽、案例约23%；E7下部约18:50:28；E9约35:37:24。数值是该页观察值，不能变成新稿固定列宽。 |
| 怎样强调 | 用蓝色标题、少量色面、细线和段内重点建立扫描顺序；深灰承载解释。局部浅底和父项框保留确有用途的分组。 | D5/D8/D9、E6/E11。两份源稿有混合字体、额外红黄色与少量阴影；新稿统一执行下述用户偏好，原样复刻另按指定范围处理。 |
| 证据用什么载体 | 关系图表达归属或传递；数据比较用图表；精确查数、评价规则与二维分类按各自逻辑呈现。图、表、解释可以在一页保持不同身份。 | E3排名与统计证据；E7/E9二维分类；E13框架、权重、评级与矩阵。源稿部分图表是图片或形状模拟；要求编辑时重建原生对象，不继承栅格结构。用户未指定表格时不把观点页默认排成行列表格。 |

两份共同点是白底蓝色体系、信息层次明确、图形与完整正文对应、整页主次随内容调整。D侧重问题、链条、投入及组织机制的局部展开；E侧重顶层架构与多个决策工具组合。选择符合当前内容的做法，不固定轮换参考页。

## 可复用参数与组件

[consulting-tokens.json](consulting-tokens.json)提供1280×720起始画布、字号、边距与线宽，坐标单位为px，字号换算为`pt=px×0.75`。这些数值支持试排，正文容量由当前文字及实际渲染决定。

- 默认16:9、微软雅黑`Microsoft YaHei`、原生可编辑、无阴影。无明确演示需求时保持静态。
- 品牌颜色以用户现有[ciic-palette.json](../../mck-ppt-design/references/team/ciic-palette.json)为唯一数值来源：主蓝`#0042FF`用于新稿标题及主强调，深灰`#383838`用于正文，背景为白色，辅助蓝按其色阶使用。源主题的`#1C55FE`属于允许的图表色1，不替代默认主蓝；禁止把微软雅黑UI当作微软雅黑。
- 标题表达核心观点；常规新写页面通常控制在6项内。来源已有层级、项数和名称优先，不能为满足默认上限改结构。
- 原生图形组件见[scripts/consulting-components.mjs](../scripts/consulting-components.mjs)：基础文字、线条、层级屋顶、分组区域及开放说明。层级窄标签使用`layerLabel`封装背景与完整文字：禁用自动折行，仅保留显式换行，先按内边距和行数检查宽高；容纳不下20px文字时要求重排，不截字或缩到不可读。该预检为保守估算，仍须检查最终文件重新导入后的实际渲染。将组件复制到已有运行依赖的项目目录使用；当前内容的数量和关系重新映射。组件不绑定真实客户文字，不复制源页标识及联系方式。`normalizePptxDefaults`仅用于本次新建候选稿的主题归一：设置中西文和主题字体、统一主题颜色、去除阴影等默认效果；完成后重新导入并渲染。不要用它改写需忠实保留的参考原件。复合页使用`pageFrame`按实际标题与总述分配高度，使用`richText`保留段内层次，斜面阶段图使用`continuousSlope`共用边界；富文本长run在当前导入渲染中可能另起行，须按最终显示预留高度或改为完整正文加就近强调标签，不能仅按段落数估算。不要把固定标题高度、方点或大色条当作整页默认。

## 制作顺序

1. 记录来源各层的名称、项数、顺序、父子关系、必要条件；确定新写、沿用原文或忠实复刻的范围。
2. 按六项选择选取具体D/E页，并沿[综合方法](consulting-page-design.md)查找A/B/C关联构图。实际查看对应预览，在私有制作记录中写明参考页、借鉴位置及迁移边界。
3. 先分配全页主图、正文与证据，再画内部子图。层级页检查共同父项，混合页检查各组边界，开放页检查阅读顺序。没有来源方向的连线保持无向。
4. 新风格或复杂框架先做少量内部样页，覆盖完整的专业对象、行动要求与多种内部关系。与来源同尺度并排，由独立审阅者提出具体差距并完成实质修订后，再扩展全稿。已有足够明确的用户要求时继续制作，不增加样页审批环节。
5. 原生制作文字、图形、图表和指定表格。渲染全部最终页面，先查内容结构与句意，再查视觉、字体、颜色及编辑性；修正后重渲染受影响页。

## 视觉验收

| 检查 | 通过标准 |
| --- | --- |
| 整页主次 | 第一眼可找到主题和主图；主图、解释及证据的面积分配符合本页内容。缩略图检查节奏，大图检查每页完整细节。 |
| 关系与归属 | 原文每层项数、顺序和父子关系完整；框线准确归组；并列不变成流程，1+3不变成四个同级独立项。 |
| 正文与字号 | 无遗漏、孤立标点、错误断词、遮挡或越界。正文不依赖备注，数字、英文和中文均为微软雅黑；显示清楚后才确认字号。 |
| 色面与连线 | 色面有分组用途，颜色来自统一色板；箭头方向有依据，线端点明确，不跨标题、不穿正文；没有阴影。 |
| 证据及编辑性 | 数据、单位和口径正确；原生对象能分别选中编辑；无整页截图替代编辑要求；文件可重新导入并打开。 |
| 参考迁移 | 有同尺度对照、具体功能映射及修订记录；相近轮廓须承担相应的信息工作。无溢出、零图片、形状数量或字体一致均不能证明设计达标。不复制样本的公司信息、二维码、示例数据及未经支持的结论。 |

E6标题写五大保障，正文及E11实际列四项，此处存在来源数量不一致；迁移时按当前内容核定。D5/D7/D9、E6/E11等页在本次转换中出现部分换行或文本拥挤，旧预览与本次显示有差异。将它们记录为转换或排版问题，按最终输出实际修复。两份文件均含图片或混合字体，用户的新稿偏好优先。
