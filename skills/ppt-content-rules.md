# PPT 文字与原文结构要求

这是用户对所有 PPT、幻灯片、文章框架图、图片转可编辑幻灯片及其审查流程的共同要求。使用相关技能时必须读取并执行。用户在当前任务中的明确指示优先；字数、短标题、信息密度、叙事套路和模板槽位等默认规定，均不得改变以下要求。

制作或改版时同时执行[PPT艺术构图与展示要求](ppt-art-direction.md)：默认采用有艺术感的非表格构图，沿用原文完整表述，保留有作用的留白。用户指定原样复刻、模板或表格保留范围时按其明确要求处理。

## 一、文字必须让读者直接读懂

- 原文能直接读懂时，优先使用原句、原标题和关键名词，通过换行、字重、位置和图形关系组织页面。精简图形、增加留白、重设计或提高艺术感均不授权精简文字；用户明确要求沿用原文时，按阅读顺序拼合后须逐字核对，排版空白除外。
- 使用自然、正式、完整的汉语。正文需要说明谁做什么、对象是什么，以及原文中影响判断的条件和关系。分类名称和指标名称可以使用准确的名词，论证和操作要求应写成读得懂的句子。
- 不为显得简洁而删去必要的主语、谓语、介词、连接词、适用范围、责任主体或评价条件。不堆砌名词，不临时拼造管理术语，不用几个关键词代替原文需要解释的内容。
- 不设强制的每点字数、标题字数或每页字数目标。可以删去确实重复的措辞和无实际内容的修饰，必须保留原意、论证关系和理解所必需的信息。
- 润色不得自行补充原文未支持的事实、公式、指标阈值、因果判断或职责。无法确认的专业口径沿用来源并标明疑点，不能用更顺口的措辞改变其含义。
- 专业名词前后一致。缩写、上位概念和指代词只有在本页能明确理解时才可使用。正文应让目标读者独立理解，不能依赖作者的口头解释或备注补足意思。

示例用于说明表达完整程度，实际改写必须以当前来源为准：

| 压缩后难以理解的表达 | 在来源支持时可采用的完整表达 |
| --- | --- |
| 经营投资匹配偿付能力与融资负担 | 经营和投资计划应与企业的偿债能力和融资负担相适应。 |
| 回款迟缓：分解逾期应收账款实际回收额 | 对应收账款回收较慢的企业，可将逾期应收账款的实际回收额分解到责任单位。 |
| 因企设标、差异赋权 | 根据企业承担的职责和经营重点，确定考核指标及各项指标所占的权重。 |

## 二、严格保留原文框架和项数

- 设计前完整阅读来源，记录原文各层级的标题、同层项数、顺序、父子关系、原有编号和关键名词，并记录每项在成品中的位置。无显式标题的段落也要识别其从属关系，不能把例子和限定条件当成独立论点。
- 原文同一层有两点，成品在该层必须保留两点。不得拆成三点、合成一点、删掉一点、补出新点，或先拆后合伪装成项数不变。各层级均按此核对，不能只检查顶层标题数量。
- 保留原有顺序和论证关系。并列事项保持并列，阶段关系才使用先后箭头；例子、适用条件、核验要求和某一阶段的进一步要求，继续放在其所属条目内，不提升为同级事项。
- 不因咨询框架、金字塔原则、结论先行、MECE、三栏模板、对称布局或默认每页项数而重构来源。只有用户明确要求重组逻辑、合并或拆分原文时，才按其授权范围调整。一般的精简、优化、美化、制作框架图不构成改变原文框架的授权。
- 内容可以跨页延续，但须保留原标题、编号及所属关系，明确标示续页。分页数量可以增加，论点数量和层级不得变化。用户限定页数时，先在完整表达和原文结构不变的条件下解决布局。
- 若有结论、总览或摘要，其核心事项须与原文相应事项逐一对应，保持名词一致，不增加、拆分或合并论点。来源结构优先于任何默认项数上限。

## 三、让版面适应内容

- 先确定结构准确、表达完整的文字，再选择版式。模板栏位与来源不符时，调整版式；不得把两点改成三点来填满三栏。
- 文字放不下时，依次考虑删去无关装饰、调整文字区域和布局、采用更合适的画布比例或在同一条目下分页。不要把必要解释移到备注、缩成关键词，或缩小到目标阅读场景中难以辨认的字号。
- 只有在不损失信息和关系的前提下，才可进行简洁改写。不能把版面字数达标视为表达合格，也不能因为内容密度达标就停止审查。
- 对原图文字做忠实重建时，遵守用户明确的原样还原要求。保留可辨认文字；无法辨认的内容保留图像证据并标注待核，不能猜写、删去或用泛化短语替代。新写或经授权改写的文字执行本文件的自然表达要求。

## 四、交付前分别审查结构和文字

先对照来源检查所有层级的项数、顺序、父子关系、编号、名词和图形关系；再脱离原文，独立阅读每页或每幅图，检查目标读者能否理解句意和操作要求。两项审查分别记录具体问题及修正结果，有条件时由独立审稿角色复核。

出现下列任一情况都必须返修：原文两点变成三点或一点；例子被升为论点；因果或先后关系被改变；只有作者知道其含义的短语；为了省字删去必要关系或适用条件；正文需要借助备注才能读懂。不得用视觉评分、平均分、渲染成功或文件格式校验抵消这些问题。结构与表达都通过审查后，才可交付。
