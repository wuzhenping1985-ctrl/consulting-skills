# 框架演绎版式规则

Use this reference when converting Chinese text reports into consulting-style image PPT pages and the user expects framework-like logical exposition rather than table-like listing.

## Core Principle

For a report-grounded slide, first identify the source text's reasoning relationship, then choose a visual structure that makes that relationship visible. Do not start from a table, grid, or equal-sized cards unless the source is genuinely a tabular comparison.

The slide body should answer: "How do these points relate, support, cause, constrain, sequence, or transform each other?" A good framework page lets the reader see the logic path before reading every sentence. The wording inside that framework should come primarily from the source report, not from newly invented consulting labels.

## Framework Archetypes

Choose one primary archetype for each normal content slide:

- House / pillar framework: use when several capabilities, conditions, or mechanisms support one upper goal, judgement, policy requirement, or output.
- Layered architecture: use when the source has levels such as regulator -> group -> subsidiary, strategy -> mechanism -> action, or policy ->制度 ->执行.
- Process lane / stage-gate: use when the source describes sequential work, implementation route, review flow, or before-during-after logic.
- Causal chain / problem tree: use when the source links issue -> reason -> impact -> response, or symptom -> root cause -> consequence.
- Responsibility boundary frame: use when the source distinguishes governance owner, implementation owner, supervision role, authorization boundary, or decision rights.
- Funnel / evidence-to-insight path: use when multiple facts, documents, interviews, or data points converge into a diagnosis or conclusion.
- Wheel / closed loop: use when the source describes recurring management cycles such as budget -> execution -> assessment -> clearing -> optimization.
- Value chain / operating chain: use when business links, functions, or management activities transfer value or responsibility from one node to another.
- Matrix with interpreted axes: use only when the two axes have clear meaning and create differentiated judgement zones. Label the axes and zones; do not render a plain table.
- Comparison columns with convergence: use when comparing groups, current/target state, policy/current制度, or alternatives, and show what the comparison proves.

## From Text To Framework

For every slide outline and prompt, specify:

- `logic_archetype`: the selected archetype.
- `reasoning_path`: the source-grounded logic the reader should follow, such as `政策要求 -> 制度覆盖 -> 缺口判断 -> 优化方向`.
- `framework_mapping`: how each source point maps into the visual structure, such as roof, pillars, foundation, lanes, stages, axes, boundary zones, or loop nodes.
- `why_not_table`: one short note explaining why this structure is more informative than a simple table, unless a true source table is being preserved.

## Layout Requirements

- Use differentiated visual roles: roof / foundation / main beam / pillar / side wing / axis / lane / gate / loop node / convergence point / boundary zone.
- Vary size, direction, nesting, and connection. The layout should show priority, hierarchy, dependency, sequence, or causality.
- Use arrows, brackets, braces, numbered flow markers, vertical levels, or connecting rules to make the reasoning path visible.
- Keep report text grounded and readable. Use short source-faithful phrases in structure labels and one-sentence explanations in key nodes.
- Prefer exact source phrases for visible labels, especially source level names, ordinal labels such as `第一 / 第二 / 第三`, judgement questions such as `这里要回答的是`, and source summaries such as `归纳起来`.
- If a page needs many details, use a main framework plus compact supporting cells, not a uniform spreadsheet-like grid.

## Avoid

- Plain 2x2, 2x3, or multi-row grids where every cell has the same visual weight and no explicit logic relation.
- Tables used merely to fit many bullets on one page.
- Repeated rectangular cards with icons or numbers but no causal, hierarchical, or procedural link.
- Decorative "framework" shapes that do not encode the source logic.
- Invented consulting frameworks, dimensions, conclusions, or management judgements not supported by the source report.
- Polished self-created summary slogans that are not source wording or that are disconnected from the source hierarchy.

## QA Failure Conditions

A consulting/report content slide fails if:

- It could be converted into a Word table without losing meaning.
- The body is only a set of independent boxes and does not reveal the logic path.
- It uses a matrix but the axes, zones, or judgement criteria are not source-grounded.
- It repeats the same card/grid composition across multiple pages despite different source logic.
- It looks like a template framework but the placement of text has no analytical meaning.
