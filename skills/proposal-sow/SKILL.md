# Proposal SOW

## Core Workflow

1. Clarify client situation, decision need, project sponsor, stakeholders, and urgency.
2. Translate pain points into project objectives and measurable outcomes.
3. Define scope boundaries: included, excluded, optional, and assumptions.
4. Build workstreams with activities, methods, data inputs, workshops, and deliverables.
5. Create project governance: steering committee, working team, cadence, decisions, and escalation.
6. Define timeline, milestones, dependencies, team roles, and client responsibilities.
7. State commercial assumptions and risk controls clearly.

## Output Standard

Use proposal language that is specific and action-oriented:

- Client context and challenge.
- Objectives and success measures.
- Proposed approach and workstreams.
- Key activities and methods.
- Deliverables and acceptance criteria.
- Timeline and governance.
- Team structure and roles.
- Assumptions, exclusions, dependencies, and commercial notes.

## Guardrails

- Do not overpromise outcomes outside consultant control.
- Do not leave scope boundaries implicit.
- Do not write vague deliverables like "analysis report" without acceptance criteria.
- Mark any legal, tax, audit, investment, or technical due-diligence dependencies clearly.
